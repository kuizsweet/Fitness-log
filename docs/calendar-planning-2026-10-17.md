# 日历规划与四态标记

## 行为

- 日期点击保留选择/查看当天记录，同时对没有具体内容的日期按「休息 → 力量 → 有氧 → 混合 → 休息」循环。
- 力量蓝色、有氧绿色、混合紫色、休息灰色。图例按「力量、有氧、混合、休息」排列。日期按钮可访问名称包含分类；混合不是仅依赖颜色表达。
- 分类直接复用 `workout_sessions`。没有训练记录时建立真实的空计划；混合对应一条力量、一条有氧计划，可从原有训练编辑器补充动作。
- 新空记录状态为 planned，不填写动作、重量、次数或已完成时间；过去和未来都可以安排，不把规划当作已经完成的成绩。
- 有动作、备注、开始/结束/暂停时间、进行中/暂停状态或导入来源的日期锁定。点击仍可查看该日，但不改变分类。锁定在服务端再次验证。
- 对可编辑的空记录优先复用 ID；切回休息或混合改为单项时，只软删除不再使用的空记录。已有回收站仍能查看和恢复。
- 空计划列表用「力量训练／有氧训练」区分两个入口，不增加另一套日程或独立标记存储。

## 保存与数据边界

- 使用三个 security invoker 函数：只读日状态、原子设置分类、限定单月的聚合读取。没有新增数据表、表字段、训练类型枚举，也未修改 RLS、认证配置。
- 请求验证登录账号、来源、2020–2030 日期、四态及版本指纹；版本冲突会重新读取并显示可重试错误。
- 每日期请求串行发送；快速点击立即显示目标颜色，只发送必要的后续目标。失败时显示已确认的数据，保留未保存意图供重试。
- 更新同月份的分类缓存；当天记录、相关详情和计划缓存精确失效；不使其他月份、活动训练或其他账号的缓存一起失效。
- 数据库迁移 `202610170002_calendar_planning.sql` 已通过现有迁移器应用；合并安装脚本同步更新。

## 验证

- 69 项测试通过，包含四态顺序、快速点击、失败重试、用户隔离、计划复用、软删除、具体内容锁定、版本冲突及日期边界。
- 独立 PostgreSQL 测试覆盖 SQL 函数和 RLS；真实 Supabase 使用已配置测试账号、authenticated 角色，在回滚事务内验证四态及动作锁定。测试前后该测试日期记录数量均为 0，未留下安排。
- 用户在实际页面设置后，刷新验证了分类持久化；混合日期关联两条真实空计划，力量和有氧入口可区分。未由代理在用户账号中添加演示训练。
- 原有固定六行、2020–2030 范围和卡片布局保留。此前七/八/九月同尺寸；本次只增加第四色和排序，不动态改变网格行数。
- 年月候选项限定深色：`color-scheme: dark`、候选背景 `#191919`。浏览器计算样式已验证。系统原生候选弹层不进入浏览器页面截图，因此截图展示关闭后的日历。
- 类型检查、Lint 与 Webpack 生产构建通过；不宣称默认 Turbopack 本机问题已解决。未提交、推送或部署。
