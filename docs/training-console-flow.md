# 训练控制台操作逻辑

## 初始状态

- 灰色计时区保留在原位置，显示 00:00，计时控制暂不可用。
- 下方两列固定为力量计划、有氧计划。当前迭代明确选用配置页现有“胸三头”便签作为力量计划，不注入另一张示例便签；有氧暂无计划。
- 从当前登录用户的工作台 drafts/已保存快照读取。优先匹配胸三头便签，其次读取今天已安排的便签；没有来源时显示空态，不构造示例数值。
- 右侧物品区保留添加框、清单、勾选、排序及删除，移除整个 Plan/List 切换；训练计划入口移至左侧。

## 状态与操作

| 当前状态 | 操作 | 结果 |
|---|---|---|
| 未开始 | 开始训练 | 快照计划；第一个动作第一组从 0 向上计时 |
| 本组训练中 | 完成本组并开始休息 | 记录本组实际重量、次数和训练时长；休息立即从 0 计时 |
| 休息中 | 选择 RIR | 写入刚完成的组；未选时推进按钮灰色禁用，选中后黑色可用；再次点击同项取消 |
| 休息中，仍有下一组 | 结束休息，开始下一组 | 固定上一组休息时长，下一组从 0 计时 |
| 动作最后一组的休息中 | 开始下一个动作 | 按便签顺序进入下一动作的第一组 |
| 全部组完成后的休息中 | 结束训练并保存 | 保留最后一次 RIR/休息记录；保存到现有 sessions 接口 |
| 训练或休息计时中 | 暂停/继续 | 暂停期间不累计，右上角标记黄色；仍可完成本组或在选好 RIR 后结束休息，下一阶段自动从 0 计时 |
| 训练或休息中（含暂停） | ±5 秒、±15 秒 | 调整当前阶段已用时间，最低为 0，不修改其他阶段 |

休息是正向已用计时，不是倒计时目标。手动调整值计入本阶段记录。

## 计划、记录与恢复

- 展开已填写组数的热身、正式、回退块，每组保持独立 ID。空子行跳过，不强行补齐。
- 不修改原便签。开始时保存计划快照，之后编辑配置不重排已开始的训练。
- 本组重量、次数可在工作态调整，完成时写入实际值；缺值拒绝完成，0kg 可用于自重。
- 完成记录按实际组保存动作名、组别、重量、次数、RIR、训练/休息时长。
- RIR 3+ 以数值3和 RIR 3+ 标签共同保存，保留“至少3”的含义。
- 完成记录入口和下拉菜单暂时移除，保留底层逐组记录与撤销逻辑，待后续确定入口位置；尚无完成组时可以返回计划。
- 整次训练完成后，下方恢复两列：左侧明日待训力量计划，右侧有氧训练，中间分隔线。力量读取明日实际安排，无安排显示空态。
- 时间计算复用旧秒表提取的 stopwatchElapsed：基准时间加时钟差值，而非累加 interval tick。原秒表 UI 不再挂载。
- 活跃状态/记录保存在当前用户的本机训练快照；切页、刷新、后台后继续读时间差，暂停保持不变。
- 同一用户其他窗口更新快照时同步读取；提交前检查快照，防止静默覆盖。

## 数据库保存

结束训练时使用当前 sessionSchema 和 POST /api/sessions，记录 training_type=strength、completed 状态及逐组内容。
保存失败明确提示“本机已保存、数据库保存失败”，允许重试，不显示假成功。
重试先按固定 session ID 查询，防止 POST 已完成但响应丢失后重复创建。
这一步不会自动将配置页所有便签变成云端计划；仅保存本次已完成训练。
