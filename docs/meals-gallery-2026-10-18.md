# 三餐图库与照片翻转

- /meals 改为左侧双列照片历史、右侧当天餐次记录，窄屏当天记录在前。历史按24张分页，支持全部、按日期以及打乱当前已加载照片的随机回顾；读取真实私有照片签名URL，不放示例餐图。
- PhotoFlipCard 同时用于历史和当天照片。正面点击后360ms翻转，背面中心编辑独立备注；inert/aria-hidden防止键盘进入不可见面，Escape返回照片，翻回再打开保留当前输入；prefers-reduced-motion取消翻转过渡。
- 历史查询新API /api/meal-history 使用已有照片/餐次RLS和私有存储，24+1分页，不读取其他用户数据。照片备注PATCH不会改变原删除状态；软删除、撤销、替换及恢复继续可用。
- 新迁移202610180001_meal_gallery.sql增加meal_photos.notes、meal_entries.calories并扩展snack餐次。不改旧餐备注、不删记录、不改RLS。
- **远程迁移已应用。** 用户随后明确要求“接上数据库”，2026-10-18 已成功执行迁移并确认 RLS 和私有存储保留。此前暂不迁移的限制已由此次明确授权更新。当前新增保存能力通过 /api/meal-capabilities 检测，无字段时显示尚未启用并禁用相应保存入口，原早餐/午餐/晚餐照片仍可使用。
- 热量按各餐可选整数输入并汇总当日，空值不显示虚构的0摄入。加餐和热量输入在数据库能力开放后启用。
- 用户提供的视频路径当前不存在，布局参考已附截图。未读取视频，不声称复现其具体动效。
- 91项本地测试通过，新增真实PGlite迁移测试覆盖旧记录保留、独立照片备注、4000字边界、加餐、热量及权限。远程保存未测试、未上传测试照片。

## 本地上传与滚动区域修复
- 移除右下角热量汇总，右栏不再限制高度或创建独立滚动容器；主页面自然滚动且隐藏可视滚动条。
- 根因：用于验收的next start是production模式，Request.url重建为0.0.0.0，旧来源校验仅在development模式允许实际localhost Host，导致同机上传403“请求来源无效”。
- 将精确回环来源匹配扩展到本地生产预览：必须目标为0.0.0.0、Origin为回环地址、Host完全相同、协议和端口相同；缺失Origin、跨端口、伪造Host和外部来源仍拒绝，远程同源/正式域名规则不变。
- 91项测试通过，包括两种运行模式的合法回环、错误Host/端口、恶意来源及缺Origin情形。远程数据库已按后续明确授权迁移。
