# kuizFit 现有功能体验审查 · 2026-10-22

## 范围与基线

- 模式：重点体验审查，非逐页逐组件全量审查；只审计，不修改应用源码。
- 运行：localhost:3003，已登录的当前用户，真实浏览器操作与只读源码交叉核对。HEAD 为 9267cac，页面包含当前未提交的工作区修改。
- 检查：配置页的动作搜索、器械筛选、动作排序、卧推子行、颜色入口、肌群饼图；控制台计时/分段/暂停/重置与 Plan/List；三餐历史筛选、空态、记录卡片收起/恢复。
- 尺寸：默认 1092×871、桌面 1440×900、手机视口 390×844。不是触屏实机测试。
- 不评价：尚未接入的力量进步、控制台肌群分析占位、排行榜及未来功能。不评价照片识别、上传结果、数据库权限和云同步正确性。
- 未执行新增/删除便签、复制子行、上传照片，避免留下无法从正常 UI 清理的数据。临时计时已重置，便签颜色恢复黄色，筛选清空，视口恢复原值。对主动作排序的拖动尝试没有改变原顺序。

## 发现

### U1 · P1 · 手机配置页核心编辑区被遮住（运行确认）

390px 视口里左侧工作台 220px、右动作库 250px，共需470px；两侧互相覆盖，便签编辑内容完全不可见。侧栏收纳手势并不能代替进入页面时可用的布局。

- 用户后果：进来找不到计划和输入框，必须先学会收纳两侧，才能开始主要任务。
- 建议：窄屏默认先展示便签；侧栏按需临时展开，切换时保持当前位置。不要把三列桌面结构直接叠在手机上。
- 验收：390px 初次进入即可看到当前便签名称及一组可编辑数值；打开动作库并关闭后仍能回到相同编辑位置。
- 证据：`test-results/ux-audit-2026-10-22/config-mobile.png`。

### U2 · P1 · 主动作排序/移除路径失效（运行及源码确认）

尝试抓“上斜推胸（器械）”名称向下一行拖动，结果是文字被选中、顺序不变。去掉手柄后，主 SortableItem 没有 asHandle 或其他激活入口；拖回动作库移除也依赖这个已经不可启动的拖动。子行排序仍可用，两者需区分。

- 用户后果：添加动作后无法调整主动作顺序或移除误加动作。
- 建议：保留无六点图标外观，同时把动作名称/非输入区作为拖动入口；提供低频的上下文移除路径与可恢复反馈，不能以恢复旧图标作为唯一修复。
- 验收：从名称发起排序有效，输入框不会触发拖动；移除路径可达并有恢复方式。
- 定位：TrainingWorkbench.tsx 的 Note 主动作 SortableItem。

### U3 · P1 · 筛选菜单鼠标提交失败（本浏览器重复复现，根因待定位）

打开“所有设备”，鼠标点击“哑铃/杠铃”，菜单保持打开、触发按钮仍显示原值、结果未过滤；对同一项按 Enter 则提交成功。只读命中检测显示点击点确实落在菜单项内，因此不能直接归咎于侧栏覆盖。

- 用户后果：筛选看起来可选，实际鼠标操作没有生效。
- 建议：先复核菜单的指针事件及关闭状态时序，而非调整菜单皮肤。
- 验收：鼠标、键盘各选一次均提交；再次选同项可取消，结果与按钮文字一致。
- 证据：`filter-pointer-not-committed.png`；点击后 label=所有设备、aria-expanded=true，Enter 后 label=哑铃。

### U4 · P2 · 子行复制缺少逆向操作（可见 UI + 源码确认）

已有两个热身子行，每行有复制，没有删除、撤销或减少子行入口。当前子行又限制不能拖出。

- 用户后果：误复制造成永久的额外空行；清空数值不能恢复结构。
- 建议：添加按需出现的子行上下文操作或撤销，不必增加一排常驻按钮。
- 验收：误复制一次，可用正常 UI 恢复原来的行数与数据。
- 定位：BenchExerciseFields.tsx。

### U5 · P2 · 分析图展开后被便签遮挡（运行确认）

真实“胸三头”便签前方覆盖展开饼图的左下区域，部分标签藏在便签下面。右上圆形也缺少可见语义，初次使用者需要试点才能知道是什么。

- 用户后果：能展开却读不全；难以确认分析属于哪张便签。
- 建议：维持收起时的背景层级，展开阅读时进入独立可读层或避开便签；展开态提供简短的便签身份与统计口径，不必把文字永久铺在画布上。
- 验收：当前便签位置下所有分区标签可见，且用户能识别分析对象；图表不冒充生理刺激比例。
- 证据：`config-chart-occluded.png`。

### U6 · P2 · 三餐手机收起后遮挡历史控件（运行确认）

390px 下，收纳露出的右侧条仍覆盖历史标题栏右端，随机回顾区域被压住。展开时空态仍写“在右侧记录一餐”，但记录区域已经位于上方。

- 建议：手机收起条占用独立安全边距，或调整历史标题栏可用宽度；空态使用不依赖左右方位的文案。
- 验收：展开/收起时历史筛选全部可达，控件不位于露出条下面。
- 证据：`meals-mobile.png`；收起表现已在浏览器截图复核。

### U7 · P2 · 工作台状态与保存边界不可见（体验判断 + 源码依据）

画布上有编辑好的便签，但左侧当天和备选区域都可为空；日历另有一天显示计划。画布、仓库、日期之间的关系对作者已知，对新用户并不自解释。成功自动保存没有可见确认，登录也无法表达本地草稿边界。

- 不把尚未开发的云同步作为缺陷；问题是当前已经存在的保存/安排状态没有被准确表达。
- 建议：在便签上下文中按需显示“未安排/已安排日期”和本地保存状态，或强化拖放后的状态反馈。不要为此增加说明墙或常驻工具栏。
- 验收：用户无需刷新验证，就能回答这张便签是否已保存、是否安排到当前日期。

### U8 · P3 · 颜色入口有误触迹象（运行观察，需独立复核）

试图打开颜色入口时便签直接变蓝，随后已用键盘明确选择黄色恢复。可能与 hover 弹出、按钮位移及点击时序有关；本次不把推测当作确定根因。

- 建议：复核真实鼠标从侧面进入后首次点击的命中目标；开启调色板不应同时改变颜色。
- 验收：单独打开入口不会写入新颜色，只有明确选择色块才会修改。

## 设计布局判断（与功能故障分开）

1. **空间分配与任务频率不一致。** 1440×900 控制台左上秒表占约半宽和约570px高，实际操作仅一小块；390px 手机首屏大半仍是秒表外部空白。计时操作正常，但容器面积明显超过内容需求。建议按就绪/运行状态分配密度，减少无信息的外层空白。证据：dashboard-desktop.png、dashboard-mobile-top.png。
2. **页面有大量空间，输入却像缩小的表格。** 配置页的动作文字12px、辅助文字11px、列头10px，数值格36/36/46px；子行进一步叠加名称、复制与树线。问题不是整体要放大，而是宽度预算没有优先给主要名称与编辑区。建议按编辑任务制定便签最小舒适宽度及缩进预算，次要工具按需出现。
3. **层级规则在不同组件之间不一致。** 便签可盖图表、侧栏可盖画布、菜单独立于侧栏；各自成立的局部规则没有形成“编辑/选择/阅读/拖动”统一层级。应先定义每种状态的层级，再调阴影，而不是继续增大 z-index。
4. **材质、边界、空白承担了太多没有明确分工的工作。** 主容器、输入格、侧栏和小按钮都较浅；标题与内容的层次弱，局部看似轻，整体扫读却费力。建议保留玻璃在浮动操作层，编辑内容优先保证稳定底色、名称层级和可读边界；这属于设计建议，不是对玻璃材质本身的否定。
5. **平静外观与可发现性之间需要有明确的补偿。** 移除手柄、收纳按钮或说明不应意味着移除能力；可以通过悬停、抓取光标、边缘形状、上下文菜单提供线索，不必恢复满屏图标。保留现有作者方向，但每减少一个显式入口，都要验证用户仍能完成任务。

## 建议顺序

1. 修复鼠标筛选与主动作排序/移除；让手机默认能进入编辑。
2. 补齐复制的恢复路径，保证展开分析可读。
3. 明确保存与安排状态，修复手机三餐遮挡。
4. 最后处理秒表面积、便签字号/列宽、层级和材质角色。

没有建议重做整个产品，也没有对未开发模块打分。本轮没有执行构建、全站无障碍扫描、真实触屏操作、照片上传或数据库端验收。
